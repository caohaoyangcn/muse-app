# 生成的图片：归属与清理

收藏是引用，数据库只保存路径；但**缩略图和刮削封面是应用自己生成的文件**，它们没有"外部真相"可依，
一旦失去对应的记录就是纯粹的垃圾。本文说明这些图片存在哪里、什么情况下会变成孤儿，以及应用如何
保证它们不会无限增长。

## 1. 文件布局

| 路径 | 生成者 | 命名 |
| --- | --- | --- |
| `<dataDir>/thumbnails/<id>.jpg` | `backend/thumbnail`（自动缩略图 / 自定义封面帧） | 记录 id |
| `<dataDir>/covers/jav/<id>.jpg` | `backend/jav`（刮削封面下载） | 记录 id |

两者的命名规则相同且**只由记录 id 决定**：`<id>.jpg`。这是清理能够安全进行的全部依据——
文件名就是归属声明。

刮削封面下载过程中会在 `covers/jav/` 临时写入 `.cover-*` 文件，重命名后即消失；它们不匹配
`<id>.jpg`，任何清扫都不会碰。

## 2. 孤儿是怎么产生的

正常移除（`video.Service.Remove`）会直接删掉记录对应的两个位置（`thumbnail_path` 指向的文件 +
`<id>.jpg`）。但删除动作**不可能覆盖所有交错**：

1. **下载晚到**：刮削任务读到记录后开始下载封面，下载完成时记录已被删除，`covers/jav/<id>.jpg`
   被重新写回。删除时文件还不存在，无法删。
2. **旧版本遗留**：本次改动之前的所有构建只在 `thumbnail_path` 非空时删除，且用
   `filepath.Base` 拼 `<dataDir>/thumbnails/`，需要删 `covers/jav/` 下的刮削封面时路径是错的。
3. **数据目录被恢复/迁移**：`app.db` 与图片目录不同步（备份不完整、手工拷贝）。
4. **崩溃**：删记录与删文件之间进程退出。

这类文件的共同特征是：**磁盘上存在 `<id>.jpg`，而 `videos` 表里没有 id 对应的行**。判断它不需要
任何启发式，只需要一次对账。

## 3. 清理策略

对账而非"追踪每个写入者"——后者要覆盖上面每一种交错，前者的判断永远只有一条查询。

`video.Service.RemoveOrphanedImages()` 读取 `videos` 的全量 id，然后遍历两个目录，删除
`<id>.jpg` 且 id 不在集合中的文件，返回 `{Scanned, Removed, Bytes}`。

触发点：

- **启动后后台一次**：`main.go` 的 `OnStartup` 调用 `StartImageSweep`，首次立即执行，之后每 24 小时
  一次。启动不等待它（首次浏览不能被一次目录遍历拖慢）。
- **移除后后台一次**：`Remove` / 已删除的重试都调度一次异步清扫，用来收拾上面第 1 种晚到文件。
- **HTTP**：`POST /api/maintenance/orphaned-images`，让无桌面的局域网部署也能执行。

### 3.1 安全边界

清扫只在**确认文件是应用生成的图片、且记录确实不存在**时删除：

- 只认 `<十进制正整数>.jpg`。`abc.jpg`、`999.png`、`999.jpg.bak`、`.cover-*`、`0.jpg`、`-5.jpg`、
  以及名字是图片的**目录**，全部原样保留。
- 只遍历 `thumbnails/` 与 `covers/jav/`，不递归，不碰数据目录里的其它内容。
- 只删文件，永不动 `videos` 表，永不触碰源视频（全局原则 `spec-v1.md` §41）。

代价是：用户若在 `thumbnails/` 里手工放一个恰好叫 `<某个不存在 id>.jpg` 的文件，它会被删掉。
这两个目录属于应用的生成物，这个取舍写在文档里而不是靠猜。

### 3.2 为什么不做"定期全盘扫描"

图片永远只在启动、导入、移除、刮削这几条路径上产生，孤儿只可能出现在上述交错中。24 小时一次的
对账加上每次移除后的清扫足以覆盖；更频繁的扫描没有额外收益，只是让磁盘空转。

## 4. 不负责清理的内容

- **`covers/jav/` 之外的刮削产物**：无。
- **已删除的人脸识别功能**：`<dataDir>/faces/`、`<dataDir>/ai/`（本机实测 866 MB + 58 MB）是旧功能
  留下的文件，相关表已在迁移 21 中 `DROP`，没有任何代码再引用它们。它们不属于"生成的图片"的
  管理范围，也不该由图片清扫顺手删除——那需要一个显式的、告知用户的一次性迁移，见 `TODO.md`。
- **`videos` 行的元数据 / 指纹**：与图片无关。

## 5. 测试

- `backend/video/imagesweep_test.go`：
  - 两个目录里的孤儿都被删除，有记录的图片全部保留；
  - 非应用命名的文件（含临时文件、错误的扩展名、图片名目录）一律保留；
  - 目录不存在时返回空结果而不是错误；
  - 记录删除后晚到的封面会被下一次清扫清掉；
  - 旧版本留下的孤儿在首次清扫时被清掉；
  - `StartImageSweep` 立即执行、可停止、`stop` 可重复调用。
