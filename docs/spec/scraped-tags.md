# 刮削标签筛选与「马赛克破解」标记

> 状态：已实施（2026-11-18）。用户自定义分组已下线，收藏库的分类维度改为刮削返回的标签。

## 1. 背景

收藏库原先有一套用户自定义分组：分组树、父子嵌套、拖拽排序、把视频拖进分组、右键「添加到分组…」。维护成本高，而且同一部片子在刮削结果里本来就有题材标签（`video_jav.tags_json`），用户需要的是「按标签找片」，不是再手工维护一套目录。

本次改动：

- 移除分组的模型、存储、API、桌面 UI 与移动筛选；
- 把 `video_jav.tags_json` 投影到共享读模型 `Video.tags`，两端用它做标签筛选；
- 保留「马赛克破解」Badge，但改为持久化标记，不再依赖分组。

## 2. 标签从哪来

- 来源：刮削结果 `video_jav.tags_json`（JavBus `genre`、Avmoo `genre`、FC2 的 `tags` 等）。
- 投影：`jav.Service.TagsByVideo()` → `api.Library` 的 `videoReadModel.tags` → `Video.tags`。
- 规则：
  - 只包含未进回收站的收藏；
  - 不按 `override_mode='skip'` 过滤——`skip` 只抑制卡片上的番号/标题，题材标签仍可用（与「类似影片」打分一致）；
  - 去空白、去重，保留刮削返回的顺序；
  - 没有标签的收藏输出空数组，不输出 `null`；
  - 标签读取失败只让标签为空并记日志，不影响收藏库主读取。

## 3. 筛选语义

`frontend/src/utils/libraryFilter.ts` 是两端共享的唯一实现：

- 字段：`tags` / `actors` / `disks`，都是多选；
- **同一栏内取并集**：选中「剧情」「巨乳」表示命中任一标签即可；
- **不同栏之间取交集**：标签 ∩ 演员 ∩ 硬盘；
- 空选择表示不限；
- 选项从当前基础列表（全库或搜索结果）派生，已选但列表里不存在的值仍以 0 计数保留，可单独移除；
- 标签/演员数量可能很大，筛选面板提供搜索与每页 20 项，已选项固定显示；
- 搜索仍是全库的标题/番号/文件名/路径搜索，再与标签筛选取交集。

标签不是用户可编辑的数据：没有新建、重命名、删除、排序或嵌套。

## 4. 「马赛克破解」Badge

- 存储：`videos.mosaic_restored`（INTEGER，默认 0）。
- 写入规则：
  - 导入/重连时文件名（basename）含 `restored` 或 `ltx`（大小写不敏感）→ 置 1；
  - 只置 1，不清零；重连结果（`Relocated`）不重新应用，避免撤销既有状态。
- 迁移：
  - v29 增加列，并按「文件名规则」+「原 `马赛克破解` 分组及其后代分组的成员关系」回填；
  - v30 删除 `video_groups` / `video_group_members`。
- 读模型：`Video.MosaicRestored` 直接来自列；卡片、详情、移动端详情继续渲染紫色 Badge。
- 分组功能下线后，不能再通过把影片放进「马赛克破解」分组来手动打开 Badge。

## 5. 4K 自动分组

原 `4K` 自动分组随分组功能一起移除。分辨率仍在卡片与详情中显示；本轮不新增「只看 4K」筛选。

## 6. 两端界面

- 桌面端：侧边栏「标签」区展示常用标签（已选项固定，最多 12 个，更多走「更多标签…」）；工具栏「筛选」打开完整面板（标签 / 演员 / 硬盘）；已选条件以 Chip 展示。
- 移动端：底部「筛选」面板同样三栏；工具栏保留排序按钮与 Chip 行。
- 排序字段与默认方向统一在 `frontend/src/utils/sortOptions.ts`：添加时间/最近播放/文件大小/点赞数默认降序，文件名默认升序。
